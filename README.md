# Agent Action Receipts — conformance test vectors

Test vectors for [draft-sahu-agent-action-receipts](https://datatracker.ietf.org/doc/draft-sahu-agent-action-receipts/):
signed, hash-chained action receipts for AI agents, verifiable fully offline.

Every vector is a newline-delimited JSON receipt log. `manifest.json` states the
expected outcome for each: which lines must fail signature verification, and the
line (if any) at which the hash chain must break.

## Provenance — why these vectors mean something

The vectors were **generated by one implementation** (the shipping TypeScript
verifier/signer behind a commercial product) and **verified by a second,
independently written implementation** (`verify.py`, Python, in this repo).
Two implementations from different codebases agree on every expected outcome.
That cross-check is the point of the suite: a third implementation that agrees
with the manifest has evidence it implements the draft, not a port of someone
else's bugs.

## Run it

```
pip install cryptography
python3 verify.py --manifest
```

Expected output: `AGREE` on all vectors. To check a single log:

```
python3 verify.py vectors/01-basic-chain.jsonl
```

## What the vectors teach

- `01`–`04` — valid chains: genesis carries no `prev_hash`; `actor` omission is
  total; unknown members are ignored by the signature; `params` objects sort
  recursively while arrays keep order; RFC 8259-minimal string escaping.
- `10`–`13`, `15`–`17` — tampering, reordering, interior deletion, duplication,
  malformed genesis, missing linkage, malformed key encoding. All must fail, at
  the stated line.
- `14-head-truncated` — **the honest limit, on purpose.** The last record is
  dropped and everything verifies clean. A self-anchored chain cannot detect
  truncation at its head; only an external head assertion can (see the draft's
  Security Considerations). A verifier that "detects" this vector is wrong.
- `18-tampered-extension` — **the differentiator.** An unsigned extension member
  is edited: every signature still passes, but the chain breaks — because the
  chain link is the SHA-256 of the previous line's *raw transmitted octets*,
  covering members the signature does not. Constructions that hash a
  re-canonicalization of the record do not catch this case.

## Contributing an independent verifier

Independent implementations are what make a format real. If you write a verifier
in another language and it agrees with `manifest.json`, open an issue or PR —
independent implementations are credited in the draft's Implementation Status
section (RFC 7942) from revision -01 onward.
